How information flows through the system

However a conversation gets in — a live mic, an uploaded recording, or typed text — it becomes transcript segments; the language model then drafts candidate requirements with traceable evidence, and the facilitator confirms or adapts them before anything is baselined.

01 · INGEST

One pipeline, three doors

Live mic (WS /audio), uploaded file (POST /transcribe), and manual text all converge on the same provider-neutral ingest path, so an upload behaves exactly like a live conversation.

02 · TRANSCRIBE

Provider-neutral speech

A SpeechToTextProvider (mock, faster-whisper, OpenAI, or Wispr) emits normalized events; ingest resolves the speaker and persists finals through TranscriptService.

03 · DERIVE

The model drafts the requirements

AnalysisService asks the LanguageModelProvider for candidate artifacts and evidence spans — each traceable to the exact transcript offset. These are proposals authored by the model, not the facilitator.

04 · VALIDATE

Humans adapt & baseline

The model never confirms its own work — a lifecycle guardrail blocks automated confirmation. The facilitator confirms, edits, or rejects each candidate, then exports the JSON + Markdown package.

Where each stage lives

The layered backend keeps every concern behind an interface, so a stage swaps without touching its neighbours.
